# AI Product Analytics Assistant

**Лабораторна робота №4 — «AI-підкріплена дата-аналітика: побудова власного аналітичного асистента».**

AI Product Analytics Assistant — прототип аналітичного асистента у форматі Google Colab Notebook. Користувач завантажує структурований CSV- або XLSX-файл, після чого Python автоматично обчислює статистичні показники, досліджує якість даних і створює графіки. Мовна модель через Groq API допомагає інтерпретувати результати та формувати текстові звіти.

Проєкт побудовано так, щоб не прив'язувати основну логіку до конкретних назв колонок або предметної області. Роботу перевірено на двох наборах даних із різною структурою: транзакціях інтернет-магазину та інформації про фільми. Це навчальний прототип: його AI-висновки потребують перевірки людиною.

## Реалізовані можливості

1. **Automated EDA.** Огляд розміру й типів даних, пропусків, повних дублікатів, описової статистики, потенційних числових викидів за методом IQR; гістограми та діаграми частот; AI-інтерпретація статистичного JSON.
2. **Hypothesis Generation.** Формування 5–10 дослідницьких гіпотез із посиланнями на числові факти, можливими поясненнями, способами перевірки та обмеженнями. Для контексту використовуються агрегати за сегментами, а за наявності відповідних дат — помісячні підрахунки.
3. **Executive Summary.** Автоматичне створення короткого управлінського огляду: ключові спостереження, ризики якості даних, бізнес-інтерпретація та рекомендації.

Усі статистичні розрахунки виконуються в Python/Pandas, а LLM використовується для генерації тексту. Валідація гіпотез перевіряє структуру відповіді та наявність посилань на факти, але **не гарантує правильність логічних висновків моделі**.

3. У Colab відкрийте вкладку **Secrets** (значок ключа зліва), створіть секрет із **точною назвою `GROQ_API_KEY`**, вставте значення ключа та увімкніть **Notebook access**.
4. Запускайте комірки послідовно зверху вниз. Перша комірка встановлює бібліотеки:

## Обмеження

- Підтримуються структуровані **CSV із типовим роздільником** і **XLSX**; нестандартні кодування, роздільники, формати дат та складні Excel-файли можуть потребувати попередньої підготовки.
- Автоматичний часовий аналіз потребує колонок, які Pandas розпізнає як `datetime`. Звичайна числова колонка `Year` не вважається датою автоматично.
- Порівняння сегментів мають описовий характер; невеликі вибірки потребують особливо обережної інтерпретації.
- LLM іноді плутає середнє та медіану, рядки й замовлення, робить помилки в порівняннях чисел або надмірно узагальнює результати. Числові факти та бізнес-твердження необхідно перевіряти за вихідними даними.
- Датасет Hollywood використано як додатковий тест переносимості; основне тестування на достатньо великому наборі даних виконано на Online Retail.
